WhereQ-DOSBox 1.0.0.15: Game Mode, a console-style gamepad for your thumb

2026年11月20日 · 阅读需 8 分钟
Dazhi Zhang (Tony)

Your thumbs are already full​

You are holding the phone in two hands and the game wants three things at once: go left, fire, jump.

The on-screen keyboard is a good way to type MOUNT C . and a bad way to play that. One thumb sits on the arrow pads, the other thumb has to leave them to find the letter B, and for a second — a second that a game with a timer does not give you — nobody is steering.

So you choose a game you can play with one thumb, or you do not choose it at all.

1.0.0.15 gives the keyboard a second face.

The console-style pads of the on-screen keyboard. This is the layout Game Mode replaces — the picture shows the pads, not the gamepad.

The pads turn into a gamepad​

Game Mode lives inside the keyboard panel. With the keyboard pads showing, switch Caps Lock on — double-tap Shift if you would rather not hunt for it — and type the code everyone already has in their fingers:

  ↑  ↑  ↓  ↓  ←  →  ←  →  B  A

The pads flip. What was a QWERTY board becomes an eight-way D-pad, a trackball, and the buttons a DOS game actually fires, jumps and strafes with: Y, X, CTRL, ALT, SPACE and ENT.

The direction pad is the one you will use most, and it is the one you will press hardest: eight directions, one thumb, no reaching.

The two letters that have to be capital​

The code is matched on the case the letters are actually typed in.

That sounds like pedantry, and it is not: type a lowercase "ba" and the emulator does exactly what you asked. It types "ba" into the DOS prompt, and you sit there at C:\> with two stray letters and a game that never started.

So the B and the A must be capital. Caps Lock is not a suggestion.

To go back, type the same code on the D-pad and then X, Y. Or press the phone's Back button, which leaves Game Mode as readily as it leaves the keyboard.

The pads on a narrower screen, where every key has to earn its room.

Every button can be remapped​

Every game wants its buttons somewhere else. The one that shoots on X and the one that shoots on Y are both common, and both are wrong for you at least once.

Long-press the gold profile button and pick Remap buttons…. Press a button on the gamepad, press the key you would rather have, and the swap is done.

The remap belongs to that one game and is remembered. The same title always plays the same way, next time and the next — you set it once and it stays.

The gamepad is a keyboard​

Here is the part I am happiest about, and it is not a feature you can see.

The gamepad sends the same SDL events the on-screen keyboard sends. The guest cannot tell the two apart. There is no new input path to teach a game, no new driver, no second set of keys for a 1994 title to be suspicious of. A button on the gamepad is a keystroke, exactly as a key on the keyboard is a keystroke.

The trackball works the same way: it sends the relative mouse events, the kind a real mouse sends, and the SDL layer now accepts them.

That is the whole design. The keyboard grew a second skin instead of becoming a new machine.

A game running in the emulator, with the keyboard's pads at the sides — the kind of game that asks for a gamepad.

Leaving the app is clean​

A smaller fix, in the same release.

A shutdown that failed used to abort the process with SIGABRT — and it did that while it was only shutting down, which is a strange time to crash. The error is caught now and the exit carries on.

I would not put this in a headline. But an emulator that dies on the way out teaches you to distrust it, and I would rather it simply left.

Your save states still load​

The save-state format did not change. Game Mode is a new way of pressing the same keys, so every save state written by the earlier releases loads normally.

This one matters more than the feature does. A release that quietly changes the format leaves a generation of slots unopenable, and the honest way to change a format is to change it loudly, with a version bump, when it really changes.

The documentation caught up​

The user guide gained a chapter on the gamepad, the technical reference gained the gamepad section and the real key path, and the interrupt map gained a case study of a finger that becomes a DOS keystroke.

And every box-drawing diagram in the documentation is now an SVG with straight borders, so the boxes look the same in every renderer and in every font.

Get it​

The release APK is signed with the release key, so it installs over the previous version in place:

👉 github.com/whereq/whereq-dosbox — tag v1.0.0.15

whereq-dosbox-1.0.0.15.apk
size:   16 500 506 bytes
sha256: dbf776abe6b69541194fa5bded5d2c807a94add4733a74ea2620b03227263f42

It runs on arm64-v8a, armeabi-v7a and x86_64 devices, Android 5.0 and newer, entirely offline, with no account and no tracking. The project is GPL-2.0, and the DOSBox core is embedded with its AUTHORS, ChangeLog, COPYING and per-file headers intact.

Again, this post is not the documentation. The documentation is the repository, and the Game Mode chapter there is the real reference — including what the buttons do when you have remapped them. Please read that rather than take my word for it.

Thank you, DOSBox​

None of this is possible without the DOSBox project.

DOSBox was written by the DOSBox Team — a volunteer crew who took an operating system from 1994 and made it runnable on every machine the world has produced since, including the ones that did not exist yet. They kept it alive for three decades and gave it away to anyone who wanted it. WhereQ-DOSBox is a thin layer on top of their work, and Game Mode is a thin layer on top of that. The originality, the craft and the generosity are entirely theirs.

This port is built on Em-DOSBox, the Emscripten build of DOSBox r4305 by Boris Gjenero, which grew out of Ismail Khatib's first attempt to compile DOSBox with Emscripten, and rode on the Emscripten work of Alon Zakai. The SDL2 library by Sam Lantinga carries the window, the audio and the touch input — and now the gamepad too, since it is the same events all the way down.

DOSBox is a trademark of the DOSBox project; this port is not affiliated with or endorsed by the DOSBox team.

A thumb can hold a direction, a button and a ball at the same time. The game, written in 1994, never has to know the difference.
