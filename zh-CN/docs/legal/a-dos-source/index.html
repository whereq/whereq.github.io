A-DOS — source code and licences

A-DOS is the Android port of DOSBox. It embeds the DOSBox emulator core, which is GPLv2, so A-DOS is a GPLv2 work as well.

GPLv2 puts two obligations on every copy of the program, and this page is where both of them are answered:

  • §2 — the licence and the copyright notices have to travel with the program. The app carries them: open the game launcher and tap Licences in its footer to see the full GNU General Public License version 2 and the attribution notices.
  • §3 — everyone who receives the program has to receive its source as well. The complete source of each build is published below.

Verify it before you build it:

curl -LO https://whereq.github.io/downloads/a-dos-1.0.0.0-source.tar.gz
sha256sum a-dos-1.0.0.0-source.tar.gz
# 89efed3e52c2f3547f478201f0326cf755f57a514001896e77b56d85b536986c

The archive is the tree of the release commit plus a SOURCE-RELEASE.md that names the version, the commit and the build. The shipped build was made from 652ddb2 — the commit the snapshot above is taken from, so the archive is the exact source of the binary. It holds the DOSBox core with its per-file copyright and licence headers intact, the Android application, the NDK/CMake build of the native library, the desktop Linux baseline, the benchmark, the dev toolchain and the build scripts.

What this build adds​

Game Mode turns the on-screen keyboard into a gamepad: a full-screen overlay with an 8-way D-pad, a trackball and a face button, in three profiles — HYBRID, ACTION and POINT & CLICK — with per-game button remaps. It is opened from the keyboard with a Konami code and left with the hardware Back button. The implementation lives in android/app/src/main/java/com/whereq/ados/GameModeView.kt in the archive, and the release notes in docs/releases/1.0.0.0.md describe the gesture and the profiles.

The sound is tuned for a phone. The mixer's defaults (44100 / block size 1024 / prebuffer 25 ms) are tuned for a desktop; under the steady CPU load of OPL/FM music the mixer's rate-tracking loop hunts and bends a sustained FM note into an audible warble — "a beep that is only there while the BGM plays". This build runs the mixer at 48000, the native rate of most phones, with a larger block and a deeper prebuffer. It changes the audio buffering only; the latency rises by about 50 ms, which is inaudible in a DOS game. The configuration is regenerated from the asset on every boot, so the new settings take effect on the next start.

There is no foreground service. This build removes the specialUse foreground service the earlier snapshot carried, together with the FOREGROUND_SERVICE, FOREGROUND_SERVICE_SPECIAL_USE and POST_NOTIFICATIONS permissions it needed. The app declares one permission, VIBRATE. Leaving the app ends the emulator process — the emulator is normally kept as a cached process, and the save states you made are what bring the game back. The release notes in docs/releases/1.0.0.0.md describe the trade in full.

The release build cannot sign itself. bin/build.sh apk --release now fails with an actionable message when no release keystore is configured, instead of quietly signing with the debug key.

Building it​

./bin/build.sh bootstrap            # fetch SDL2 and build the toolchain
./bin/build.sh android --abis "arm64-v8a armeabi-v7a x86_64"
./bin/build.sh apk --release        # the signed APK

BUILDING.md and bin/build.sh doctor say what is missing.

SDL2 is not in the archive. third_party/fetch-sdl2.sh downloads the exact release the build uses — SDL2 2.30.0 — from

https://github.com/libsdl-org/SDL/releases/download/release-2.30.0/SDL2-2.30.0.tar.gz

./bin/build.sh bootstrap runs that fetch for you.

Try it — the example bundle​

The archive carries an example bundle: STARFALL, a tiny DOS game written for this project. It is published on its own as well, so that the bundle launcher can be seen working without building anything:

Archivea-dos-demo-bundle.zip
SHA-256fa53db56ac78ecf4dead745a247c1d970950ae0442d2763b0730e6689bf20a36
ContentsSTARFALL.COM, PLAY.BAT, README.TXT

To install it in the app:

  1. Download a-dos-demo-bundle.zip to the phone.
  2. Open A-DOS and tap the File key on the on-screen keyboard (top left) to open the bundle launcher.
  3. Tap Install a bundle (.zip) and pick the downloaded file.
  4. It appears in the list. Tap Play and the emulator reboots into STARFALL.

The app itself ships no games — this bundle is an example, published with the source code, and the user brings their own software.

The full text of the licence is in COPYING, the attribution notices are in NOTICE, and both are in the archive and in the app itself.

Earlier work​

The native port this app grew out of is public as whereq/whereq-dosbox — the DOSBox core, the JNI glue and the build scripts under GPLv2. The emulator core in A-DOS is that same code with the product name changed; what sits on top of it is A-DOS's own application layer — the Play build — and its own documentation, which is why the snapshot above is published separately.
