WhereQ-DOSBox 1.0.0.15：给拇指一个掌机

November 20, 2026 · 12 min read
Dazhi Zhang (Tony)

一根拇指终究不够用​

在手机上玩 DOS 游戏，总有那么一个瞬间：游戏不再像游戏，倒像一场手指的杂技。

你双手捧着手机，游戏却同时要你做三件事：向左，开火，跳跃。屏幕键盘拿来敲 MOUNT C . 很顺手，拿来玩游戏就很难受——一只拇指按在方向键上，另一只必须离开方向键去够字母 B，就那么一两秒，而带计时的游戏不会给你这一两秒。

于是你只挑那些单手能玩的游戏；那些要一只手按住方向、另一只手开火的作品，你干脆不碰。为打字而生的键盘，打字足够好，当手柄却不够。

1.0.0.15 给这块键盘添了第二张脸。

横屏时的按键布局：画面在中间，两只手各管一边。Game Mode 要替换的就是 这一套。

按键翻成手柄​

Game Mode 就住在键盘面板里，不用再开一个应用，也不用插什么线：手机在同一个位置，换了一套控制。

键盘显示着的时候，打开 Caps Lock（不想找它，双击 Shift 就行），然后敲一段人人都已经存在手指里的暗号：

  ↑  ↑  ↓  ↓  ←  →  ←  →  B  A

按键翻面了。原来的 QWERTY 变成一个八向方向键、一颗轨迹球，外加 DOS 游戏真正用来开火、跳跃和横移的那几个键：Y、X、CTRL、ALT、SPACE 和 ENT。

方向键是你用得最多的，也是你会按得最狠的：八个方向，一根拇指，不用够。轨迹球归另一根拇指，像笔记本触控板那样移动——划一下动一点，轻点就是点击。

Hybrid 档案：左边是 D-pad，右边是轨迹球，旁边还有两个鼠标键。

左上角那个金色按钮写着当前的档案，每个游戏都记住你上次和它一起用的那一个。Hybrid 是默认档——D-pad 加轨迹球，给那些既要键又要鼠标的游戏。Action 把轨迹球换成键盘街机游戏真正想要的键：FIRE、JUMP、USE 和 ENT。Point & click 反过来，左拇指下面是大大的 LEFT 和 RIGHT 鼠标键。

Action 档案：FIRE、JUMP、USE 和 ENT，给那些用键盘开火和跳跃的游戏。

Point & click 档案：鼠标键占满左半边，轨迹球占右半边。

要退出来，在方向键上敲同一段暗号，然后按 X、Y，这两个面部键替 B 和 A 上场；或者按手机的返回键，它退出 Game Mode 和退出键盘一样干脆。

那两个字母必须大写​

这段暗号，是按字母实际打出来的大小写来匹配的。

听着像吹毛求疵，其实不是：你打一个小写的 "ba"，模拟器就老老实实照做，把 "ba" 打进了 DOS 提示符。你坐在 C:\> 面前，屏幕上多出两个莫名其妙的字母，游戏根本没开始。

所以 B 和 A 必须是大写。Caps Lock 不是建议，是这段咒语的前半句。

方向键有三种方言​

DOS 游戏对「上」这个方向各说各话：有的读方向键，有的读数字小键盘——在小键盘那里，斜向本身就是一个键；等字母也能当操作键之后写出来的游戏，则读 WASD。

方向键下面那个按钮就在三种模式之间轮换，应用会按游戏记住你选的那一种：

模式上 / 下 / 左 / 右斜向适合
ARROWS方向键 ↑ ↓ ← →同时按两个键（↑ + →）大多数游戏——凡是读方向键的
NUMPAD小键盘 8 / 2 / 4 / 6单个键——7 / 9 / 1 / 3按小键盘做的游戏，斜向自成一个键
WASD字母 W / A / S / D同时按两个键（W + D）后来的射击游戏，以及一切绑定了 WASD 的游戏

按钮上写的就是你当前实际用的那个模式，不会一边写着 ARROWS、一边发的是 WASD。如果游戏完全不理方向键，八成是模式不对——换到它有反应为止。

每个键都能重新映射​

每个游戏都想把按钮放在自己顺手的地方。有的用 X 开火，有的用 Y，都很常见，而且多半都不合你的手。

长按那个金色的档案按钮，选 Remap buttons…。屏幕进入映射模式：可以改的按钮镀着一圈金色描边，你点其中一个，弹出一串按键，选你更想要的那个。

长按那个金色的档案按钮，选择器就弹出来——三个档案，以及进入映射页面的入口。

映射模式。金色描边标出的是可以改的键；在金色的 FIRE 按钮上，描边得是深 褐色，否则就看不见了。

这套映射属于这一个游戏，并且会被记住：同一个游戏下次打开，还是老样子。

这个手柄就是键盘​

下面这件事看不见，却是我自己最满意的部分。

手柄推上去的 SDL 按键事件，和屏幕键盘推上去的完全一样，走的也是同一条路：经过 mapper，进模拟键盘，进 BIOS 缓冲区，最后像一次真正的击键那样从 INT 09h 送出去。运行在 DOS 里的程序分辨不出两者的区别。没有一条新的输入通路需要游戏去学，也没有新的驱动需要 1994 年的游戏去提防。手柄上的一个按钮就是一个按键，跟键盘上的一个键没有区别。

这也是为什么这个手柄没向模拟器核心要任何东西：它是应用层的事，核心从头到尾都不知道它存在。

鼠标走的是另一条路：轨迹球的移动会变成相对位移的鼠标事件，和真实鼠标发的那种一样，SDL 这一层现在接受它们；点击按钮则是真正的鼠标按钮。

整个设计就是这样：键盘长出了第二层皮，而不是变成了另一台机器。

有一点它不是：它不是摇杆。背后没有模拟摇杆，应用里也根本没有手柄硬件——需要真正模拟轴的游戏，这个应用照样玩不了。

模拟器里跑着的 STARFALL。画面两边的还是键盘的按键——进了 Game Mode， 它们在同一个位置变成手柄。

存档还是读得出来​

存档格式什么都没改。 Game Mode 只是换了一种按同样的键的方式，所以之前各版本写下的存档都照常读得出来。

这一条比功能本身还重要。一次悄悄改掉格式的发布，会留下一批再也打不开的存档；老实做法是——格式真变了就大声改，带版本号地改。

每个游戏三个槽位，每个槽位背后是手机上的一个文件——整台机器装进一个 文件，1.0.0.8 干的就是这件事。

退出应用不再崩​

同一版里还带了一个小修复。

以前关机的过程中一旦出错，进程会被 SIGABRT 直接打死——偏偏是在它自己正准备退出的那一刻崩掉，这个时机很怪。现在这个错误会被接住，退出流程照常走完。

这件事我不会写进标题。但一个退出时都会死掉的模拟器，会让人开始不信任它；我更希望它只是安安静静地走掉。

拿去用​

这一版在发布页上，tag 是 v1.0.0.15。APK 由 CI 从这个 tag 构建，作为发布资产传上去，旁边还放着一个 .sha256 文件，下载下来可以自己核对。

👉 github.com/whereq/whereq-dosbox ——源代码，以及它全部的来历。

它跑在 arm64-v8a、armeabi-v7a 和 x86_64 设备上，要求 Android 5.0 及以上，完全离线，不需要账号，也没有任何追踪。项目采用 GPL-2.0 许可，DOSBox 核心连同它的 AUTHORS、ChangeLog、COPYING 和逐文件头注释一起嵌入。

刚认识这个项目的话，公告 说的是它是什么，用户手册 带你走过每一个界面；把键盘改造成掌机 讲的是 Game Mode 要替换掉的那两块按键区，活过应用的存档 讲的是那些至今还读得出来的存档。项目现在的整体状态，看 WhereQ-DOSBox；一个按键进了机器之后发生了什么，看中断表。

再说一次：这篇文章不是文档。 文档是仓库本身：用户手册 里的 Game Mode 一章、技术参考，还有中断表。请去读那些，而不是信我的一面之词。

谢谢 DOSBox​

没有 DOSBox 项目，这一切都不可能。

DOSBox 由 DOSBox Team 写成——一群志愿者把 1994 年的一套操作系统改造到此后世界造出的每一台机器上都能跑，包括那些当时还不存在的机器。他们让它活过了三十年，并免费交给任何想要的人。WhereQ-DOSBox 只是建在他们工作之上的一层薄壳，Game Mode 不过是那层壳上的另一层。原创力、手艺和慷慨完全属于他们。

这个移植基于 Em-DOSBox——Boris Gjenero 做的 DOSBox r4305 的 Emscripten 版，它又来自 Ismail Khatib 最早那次用 Emscripten 编译 DOSBox 的尝试，并且踩着 Alon Zakai 的 Emscripten 工作一路往前。窗口、音频和触摸输入由 Sam Lantinga 的 SDL2 库承担——现在手柄也归它管，毕竟一路到底都是同一批事件。

DOSBox 是 DOSBox 项目的商标；这个移植与 DOSBox 团队没有任何隶属或背书关系。

一根拇指可以同时按住一个方向、一个键和一颗球。而那款写于 1994 年的游戏，永远不需要知道这中间的差别。
