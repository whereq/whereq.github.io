那个不动的按键​

WhereQ-DOSBox 1.0.0.17：隐私政策该放在哪里

November 20, 2026 · 7 min read
Dazhi Zhang (Tony)

那份本该一直都在的文件​

隐私政策不是功能。它是一张纸，写清楚这个应用拿你的数据做什么。而 WhereQ-DOSBox 有意思的地方在于，这张纸几乎没什么可写的：它不收集任何数据，没有统计分析，没有崩溃上报，没有广告 SDK，也没有账号。

它连 INTERNET 权限都不申请。不是"申请了没用"——是根本没有申请。manifest 里没有那条权限，所以这个应用在物理上就没法把任何东西发到任何地方去。

所以政策本身从来都不是难点。难的是决定它该放在哪里，而我一直把这件事当成应用的问题，其实它是一个产品的问题。

WhereQ-DOSBox 1.0.0.17: where a privacy policy belongs

November 20, 2026 · 7 min read
Dazhi Zhang (Tony)

The document that should have been there already​

A privacy policy is not a feature. It is a piece of paper that says what the app does with your data, and the interesting thing about WhereQ-DOSBox is that there is almost nothing to say: it collects nothing, it has no analytics, no crash reporting, no advertising SDK and no account.

It also does not ask for the INTERNET permission. Not "does not use it" — does not ask for it. The app physically cannot send anything anywhere, because the manifest does not contain the permission that would let it.

So the policy itself was never the hard part. The hard part was deciding where it should live, and I had been treating that as a question about the app when it is really a question about the product.

WhereQ-DOSBox 1.0.0.14: a save that timed out no longer answers the next request

November 19, 2026 · 7 min read

You pressed Save twice​

You were halfway through a fight with something large. You pressed Save.

Nothing came back. The slot did not fill, the spinner did not spin, and the phone was busy for a second — long enough that you pressed Save again, because the first press clearly had not registered.

The second press did register. It saved. And that was the problem: the file that went to disk was not necessarily the file that the second press asked for.

WhereQ-DOSBox interrupts: the map of every INT in the emulator

November 19, 2026 · 14 min read
Dazhi Zhang (Tony)

The one interface every DOS program agrees on​

Here is something I did not expect to care about, and then could not stop caring about.

A DOS game from 1987 does not know what a graphics card is. It does not know that a mouse exists, or that a keyboard has a buffer. It knows exactly one thing: it can ask the machine a question by pushing a number onto the stack and executing INT. INT 10h and the machine will put a character on the screen. INT 16h and the machine will hand over a keystroke. INT 33h and the machine will tell it where the mouse is and which buttons are down.

That is the whole contract. Every game from 1991 to 1994 is written against it, and it never changed.

I have been reading DOSBox's interrupt layer properly for this article, and it turns out to be one of the most carefully built parts of the emulator — and one of the parts this port has had to think about hardest, because a touch screen is not a mouse and a phone is not a PC.

So here is the map.

"Just now"​

You come back to the game after lunch. You tap the slot that said you saved it five hours ago. The game loads exactly where you left it — the boss, the health bar, the room you were in.

And the slot now says "just now".

The save is the save you made. The game is the game you left. Only the timestamp lies, and it lies in the direction that makes the app feel like it cannot be trusted with the one thing it is supposed to remember.
