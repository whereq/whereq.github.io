Agent templates gallery

Aquarius 2027.01

The templates gallery is a marketing-driven wedge: each public template ships as a portal page + a one-click installer. Install = permanent MCP caller. Browse at api.whereq.cloud/v1/agent-templates/featured.

What is a template?

Section titled “What is a template?”

A template is a pre-built agent prompt + the exact set of MCP tools it needs. Instead of writing a Claude Desktop config from scratch, you click “install” and the template wires up the right MCP server, drops the config into the right file, and gives you a starter prompt to paste.

Each install is a permanent MCP caller — every Claude Desktop / Cursor session you open from then on is metered through the Data API and contributes toward the platform’s north-star (50 weekly unique MCP callers).

Launch templates

Section titled “Launch templates”

The gallery ships with 3 launch templates. Each is a full landing page in this section — description, MCP tools, install command, and the canonical prompt. The /templates portal page will eventually render these as separate /templates/<slug> routes; for now they’re inline so the SEO + marketing copy lives in one place.

Browse the full list (which the seed file can extend without changing this page):

morning-market-brief — Cross-asset morning brief

Section titled “morning-market-brief — Cross-asset morning brief”

“A concise cross-asset morning brief — equities, rates, FX, crypto, prediction markets. Under 300 words, the morning brief, not the daily report.”

Tools it uses (MCP):

  • market_trends — headline moves across asset classes
  • rates_fx — the rates curve (treasuries + DXY)
  • crypto_intel — fear & greed + derivatives positioning
  • prediction_markets — the day’s biggest expected events

Install (Claude Desktop):

Then run:

“Give me a concise cross-asset market brief for today. Start with market_trends for the headline moves, then rates_fx for the rates curve, crypto_intel for sentiment, and prediction_markets for the day’s biggest expected events. Call out what changed since yesterday and why it matters.”

earnings-setup — Pre-earnings analysis

Section titled “earnings-setup — Pre-earnings analysis”

“For an upcoming earnings call: pull the consensus, the positioning, the recent catalysts. Drop the result in your notes.”

Tools it uses (MCP):

  • market_context — recent news + SEC filings filtered to the symbol
  • options_sentiment — implied move + put/call
  • short_volume — squeeze risk

Install (Claude Desktop):

Then run (replace {symbol}):

“Analyze the pre-earnings setup for {symbol}. Use market_context to pull the latest news + SEC filings, then options_sentiment for implied move + put/call, then short_volume for squeeze risk. Summarize the bull/bear case and the implied move. End with one sentence: ‘the trade’.”

squeeze-scan — Short-squeeze scan

Section titled “squeeze-scan — Short-squeeze scan”

“Scan a watchlist for short-squeeze setups — high SI, low DTC, recent catalyst. Rank by squeeze potential.”

Tools it uses (MCP):

  • short_interest — most-shorted US names (DTC, SI, days to cover)
  • short_volume — short volume + settlement type (long vs short)
  • market_context — catalyst check (recent news / filings)

Install (Claude Desktop):

Then run:

“Find short-squeeze candidates. Use short_volume for the most-shorted US names, cross-check options_sentiment (high put/call, elevated IV) and market_context for any catalyst. Rank by squeeze potential.”

Why these three

Section titled “Why these three”

The 3 launch templates cover the top-of-funnel finance Twitter use cases:

  • Morning brief — daily, repeated, SEO-friendly (“morning market brief”, “daily market summary”)
  • Earnings setup — symbol-specific, high-intent (“earnings preview”, “pre-earnings analysis”)
  • Squeeze scan — viral pattern, event-driven (“squeeze candidates”, “short squeeze scan”)

Each maps to a long-tail keyword cluster. The install command turns each into a permanent MCP caller, which feeds the 50/week north-star.

Install a template

Section titled “Install a template”

The install endpoint returns a claude_desktop_config.json fragment plus a one-line bash command that does the merge. The merge is idempotent — re-running is a no-op.

For Cursor, pass ?client=cursor. For VS Code, pass ?client=vscode.

The endpoint returns:

The prompt field is the canonical starter prompt — paste it into Claude / Cursor / VS Code to run the template. Each install bumps the template’s use_count for analytics.

Field reference

Section titled “Field reference”

Create / update

Section titled “Create / update”
Field Type Required Notes
slug string yes (on create) URL-safe, [a-z0-9-]{3,60}. Unique across the platform.
name string yes 3-120 chars.
description string yes 10-400 chars. Shown on the gallery card.
prompt string yes 20-8000 chars. The canonical starter prompt.
category string no One of: market, research, macro, screener, etc.
tags string no Space-separated, lowercased on save.
tools_used string no Free-text list of MCP tool names.
is_public bool no false = private (only you see it in /mine).

List filters

Query param Effect

sort=recent by created_at DESC.
sort=forks by fork_count DESC.
limit=20 1-100.

Why this exists

Section titled “Why this exists”

The templates gallery is the second wedge on top of the MCP server (the first wedge is the MCP server itself). It addresses three problems at once:

  1. Discoverability — most users don’t know which MCP tools combine into a useful agent. Templates are pre-validated combinations.
  2. Friction — even users who know which tools they need still have to write the config file by hand. The install endpoint collapses 5 minutes of fiddling into 5 seconds of curl.
  3. Marketing — every template is a landing page indexed by Google for long-tail terms (“earnings setup”, “squeeze scan”, “morning market brief”). The first 3 templates cover the top-of-funnel finance Twitter use cases.
