Webhooks (event subscriptions + delivery log)

Capricorn 2026.12

This page was ported from the legacy /docs/webhooks route as part of the Astro 5 + Starlight migration. URLs are preserved.

Create a webhook at account/webhooks. Pick an event_type (sec_filings, earnings, screener, or prices), supply a filter config, and a destination URL.

Filter shape

Section titled “Filter shape”
Event Config keys
sec_filings { "companies": ["apple", "nvidia"] } — case-insensitive substring match on company_name
earnings { "symbols": ["AAPL", "NVDA"] } — exact uppercase match
screener { "filters": { "short_pct_min": 20, "market_cap_min": 1e10, "sector": "Tech" } }
prices { "domain": "fuel", "region": "us", "min_pct": 5 } — fires when a series posts ≥min_pct move

Signature

Section titled “Signature”

Each POST includes X-Whereq-Event, X-Whereq-Delivery, and X-Whereq-Signature: sha256=<hex>. During the 24h rotation grace window, deliveries also include X-Whereq-Signature-Previous: sha256=<hex> signed with the OLD secret so a verifier that hasn’t been updated yet can still authenticate. Delivery

Section titled “Delivery”

Retries with exponential backoff (1m, 5m, 30m, 2h, 12h). After 5 failed attempts the delivery is marked failed and your subscription auto-disables after 10 consecutive failures. View the failure log at account/webhooks → pick one → “Deliveries” tab.

Rotating the signing secret (Aquarius 2027.01)

Section titled “Rotating the signing secret (Aquarius 2027.01)”

Rotate the secret any time — generate a new one with a single POST and the platform keeps accepting the old secret for a 24h grace window so you can deploy without dropping events.

Check the rotation status:

Returns { rotated_at, grace_until, grace_active, age_hours }.

Verifying a signature (no event needed)

Section titled “Verifying a signature (no event needed)”

Don’t want to wait for a real event to test your verifier? Use POST /v1/webhooks/subscriptions/{id}/test-signature to get the canonical body + signature you can pipe straight into your handler test:

Returns { body, raw_body, signature_header, verify_with } so your test can copy-paste the expected signature and assert on it.

Or fire a real test POST to your endpoint with POST /v1/webhooks/subscriptions/{id}/test-deliver — same shape as a real event, signed with the current secret, returns the HTTP status from your endpoint.
